Doxa supports standard Markdown and GitHub-flavored Markdown. This page shows the most common elements.

## Emphasis and inline code

Write **bold text**, _italic text_, and `inline code`. Use inline code for file names, commands, and values, for example `pnpm install` or `docs/index.mdx`.

## Links

Link to another page with a relative path, for example [Quickstart](/quickstart). Link to another site with a full URL, for example [doxa.so](https://doxa.so).

## Lists

Use a numbered list when the order is important:

1. Write the first draft.
2. Ask a teammate to read it.
3. Publish the page.

Use a bulleted list when the order is not important:

- Guides explain how to do a task.
- Concepts explain how something works.
- Reference pages list every option.

Use a checklist to track work:

- [x] Write the introduction
- [ ] Add a code example
- [ ] Publish the page

## Tables

| Option | Default | Description |
| ------ | ------- | ----------- |
| `port` | `3000` | The port of the local server. |
| `open` | `false` | Opens the browser when the server starts. |
| `logLevel` | `info` | The minimum level of log messages. |

## Quotes

> Good documentation answers the question that the reader has right now.

## Headings

Use `##` for the main parts of a page and `###` for subsections. Each heading appears in the table of contents on the right side of the page.

### A subsection

Subsections appear indented in the table of contents.
